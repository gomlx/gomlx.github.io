# Contributing to gomlx.github.io

Thanks for your interest in improving the [GoMLX](https://github.com/gomlx/gomlx) documentation site!
This repo hosts the [Hugo](https://gohugo.io)-based static site published at
[gomlx.github.io](https://gomlx.github.io). This guide walks a first-time contributor through
everything needed to get a local copy running and to submit a change.

## Prerequisites

You'll need the following installed:

| Tool | Version | Notes |
|---|---|---|
| [Git](https://git-scm.com/downloads) | any recent version | to clone the repo and submit PRs |
| [Go](https://go.dev/dl/) | 1.26+ | only needed to run the `sync_docs`/`sync_code` tools (see below) |
| [Hugo](https://gohugo.io/installation/) | **Extended** v0.160.0 (or compatible) | builds and serves the site — the "Extended" edition is required (it includes the Sass/SCSS compiler) |

### Installing Hugo Extended

- **macOS**: `brew install hugo`
- **Linux (snap)**: `sudo snap install hugo --channel=extended`
- **Linux (manual .deb, matches the version used in CI)**:
  ```bash
  wget https://github.com/gohugoio/hugo/releases/download/v0.160.0/hugo_extended_0.160.0_linux-amd64.deb
  sudo dpkg -i hugo_extended_0.160.0_linux-amd64.deb
  ```
- **Windows**: `choco install hugo-extended`

Verify the install with:

```bash
hugo version
# should print something like: hugo v0.160.0+extended ...
```

If it doesn't say `+extended`, uninstall and reinstall using one of the commands above — the
non-extended build will fail on this site's Sass assets.

### Installing Go

Only required if you plan to run `make sync` (pulling docs/code snippets from the main
[gomlx/gomlx](https://github.com/gomlx/gomlx) repo). Most content-only contributions don't need it.
Install from [go.dev/dl](https://go.dev/dl/) or your package manager, matching the version in
[go.mod](go.mod) (currently Go 1.26).

## Getting the code

1. [Fork](https://github.com/gomlx/gomlx.github.io/fork) this repository on GitHub.
2. Clone your fork:
   ```bash
   git clone https://github.com/<your-username>/gomlx.github.io
   cd gomlx.github.io
   ```
3. (Optional but recommended) add the upstream remote so you can keep your fork up to date:
   ```bash
   git remote add upstream https://github.com/gomlx/gomlx.github.io
   ```

## Running the site locally

```bash
make dev
# -> open http://localhost:1313
```

This starts Hugo's dev server with hot reload — most edits to content or theme files show up in the
browser automatically. Run `make help` at any point to see all available `make` targets.

To build the production version of the site (output goes to `./public/`):

```bash
make build
```

### Alternative: Docker

Don't want to install Hugo natively? Use Docker instead — you only need
[Docker](https://docs.docker.com/get-docker/) with Compose:

```bash
make dev-docker
# -> open http://localhost:1313
```

This builds a small image with the same Hugo Extended version pinned in CI
([Dockerfile](Dockerfile)) and mounts the repo into it, so hot reload still works. Note that on
macOS/Windows, file-change detection over the bind mount can be a bit slower than a native
install — if you're doing heavy content editing, the native `make dev` will feel snappier.

The `sync_docs`/`sync_code` tools (Go) aren't wired into the Docker setup — run `make sync` natively
if you need them.

## Project layout

```
content/          # Site content, in Markdown (front matter + body)
  docs/           # Documentation pages
  examples/       # Examples section
  community/      # Community page
themes/gomlx/     # Custom Hugo theme: layouts, CSS, JS, static assets
cmd/sync_docs/    # Tool that pulls docs from github.com/gomlx/gomlx into content/docs
cmd/sync_code/    # Tool that syncs Go code snippets/output into the .md files
data/docsnav.yaml # Docs sidebar navigation structure
hugo.toml         # Site configuration
Makefile          # dev / build / sync / clean targets
```

## Making changes

### Editing documentation content

Most contributions will be edits to Markdown files under `content/`. Each page has YAML front
matter (title, section, weight, etc.) — follow the pattern of neighboring files.

**Before editing a file under `content/docs`, check whether it's synced from the main
[gomlx/gomlx](https://github.com/gomlx/gomlx) repository** (e.g. `overview.md` and `changelog.md`
are generated by `cmd/sync_docs`, and Go snippets embedded via `<!-- sync_code: ... -->` comments
are generated by `cmd/sync_code`). Hand-editing a synced file works locally but will be overwritten
the next time someone runs `make sync` — for those, the fix usually belongs upstream in
`gomlx/gomlx` instead. See [.agents/AGENTS.md](.agents/AGENTS.md) for details on how the sync
markers work. If you're unsure whether a page is synced, it's fine to open a PR and ask — a
maintainer can point you the right way.

Sidebar navigation for the docs is controlled by [data/docsnav.yaml](data/docsnav.yaml); update it
if you add or remove a docs page.

### Editing the theme

Layouts, partials, and shortcodes live in `themes/gomlx/layouts`; CSS/JS in
`themes/gomlx/assets`. `make dev` hot-reloads these too.

### Syncing docs/code from the main GoMLX repo (maintainers, mostly)

```bash
make sync              # pulls the latest release's docs and code snippets
make sync VERSION=v0.27.3
make sync BRANCH=main
make sync LOCAL_PATH=../gomlx   # sync from a local checkout of gomlx
```

This requires Go to be installed (see Prerequisites). Most first-time contributors won't need this.

## Submitting a change

1. Create a branch off `main` for your change.
2. Make your edits, and verify locally:
   ```bash
   make dev     # eyeball the change in the browser
   make build   # confirm a production build succeeds
   ```
3. Commit with a clear, descriptive message.
4. Push to your fork and open a pull request against `gomlx/gomlx.github.io`'s `main` branch.
   Describe what changed and why; link any related issue.

A GitHub Actions workflow ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) builds and
deploys `main` to GitHub Pages automatically once a PR is merged — no manual deploy step needed.
